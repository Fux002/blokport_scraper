## TIER 1 — Critical fixes (do first). 7 items: 2 are shipping wrong data today, 5 are verified high-severity.

### F1 — Inventory quantity computed at load time, in 6+ places, never a field  `[LIVE BUG]`
**Doc:** `PIPELINE_MODULARITY_AUDIT.md` §L1 (full edge cases + repro).
**Problem:** `inventory_for` (`product_state.py:71`) is re-run at every write site (emit ×2, populate ×2, render ×2) + a latent 7th with a *different* formula (`medusa_client.py:88`). Effect: **every block ships stock `0`** (unsellable), **a 0-stock slab is published as 6** (oversell), slab stock is **pinned at the config default forever** for most sources, and `Variant Inventory Quantity` vs `STN Bundle Size` **disagree within one row** on locale numbers.
**Fix:** add `CanonicalRow.inventory_quantity` (+ `inventory_method`/`_confidence`); derive it **once** in Stage 6 after `derive_bundle_size` — separate "stock" from "bundle multiplier", use `parse_number` consistently, treat literal `"0"` as trusted-0; all writers *read* the field, delete `inventory_for`; add a `validate` stock gate; fix `_stock_is_unparseable` to inspect raw inputs; decide the block policy (blocks are singletons → explicit `1`, not accidental `0`).
**Verify:** parametrize `[("0",slab),("twelve",slab),(None,block),("1,000",slab)]` asserting inventory + bundle_size + the flag.

### F2 — `derive_origin` resolves the WRONG homonym's origin  `[LIVE BUG, undercuts the just-shipped multi-country origin feature]`
**Doc:** `PIPELINE_MODULARITY_AUDIT.md` §T1.
**Problem:** origin lookups key on `row.type_name` (`derive.py:420,430`), which is only authoritative when `reconcile._apply_type` overrode it. When a matched row's `variation_key` yields no recognized type slug, reconcile **re-stamps the name-derived type as `variety_authoritative` (high conf)** and `derive_origin` resolves a homonym's origin confidently, **no flag**.
**Fix:** in `reconcile_tree._apply_type`, use a **distinct `type_method`** when it falls back (don't claim `variety_authoritative`); have `derive_origin` drop to `supplier_default` + flag when the type isn't genuinely variation-authoritative. Leave States 3 & 4 (`type_overridden_by_variety`, variety-absent) alone — they're correct.
**Verify:** matched row, `variation_key` with unrecognized type slug, homonym in origin_map both types, normalize-set type → assert origin comes from the bound type.

### F3 — Ledger product ACK marks a row `synced` after a concurrent write re-dirtied it (lost update)  `[VERIFIED high]`
**Doc:** `FULL_CODEBASE_REVIEW.md` H1. **Root:** the ACK is authoritative over the row's *current* contents, not the *served* version.
**Problem:** `sync.py:415` flips `synced` gating only on `state != 'retiring'` — not on the lease, not on the payload_hash. `populate_products` (different process) re-dirties on a content change. → Medusa holds stale content forever; ledger believes new content is live.
**Fix (server-side, no Medusa change):** make the lease a **precondition** — the synced-flip must require `state == 'syncing'` (a re-dirty moves it to `dirty`, so a stale ACK won't flip it; the row re-serves). If you also want strict correctness under lease-reap, additionally compare the served `payload_hash` — that requires round-tripping the hash through the ACK (Medusa-contract touch; coordinate). **Fix F3+F4 together.**
**Verify:** serve P (content A) → populate rewrites P to B (→dirty) → ack(P) → assert P stays dirty and re-serves.

### F4 — Ledger inventory ACK snaps stock to CURRENT qty, not served qty  `[VERIFIED high]`
**Doc:** `FULL_CODEBASE_REVIEW.md` H2.
**Problem:** `sync.py:384` does `SET last_synced_qty = qty`; inventory rows are never leased; `populate_inventory` can move qty between serve and ack → the delta vanishes → oversell/understock.
**Fix:** record the **served qty** at serve time (a `served_qty`/token column, or round-trip it in the ACK) and only clear the delta if `current qty == served qty`; otherwise leave the delta so the new qty re-serves. (Inventory isn't leased, so unlike F3 it needs an explicit served-value, not just a state check.)
**Verify:** serve X@5 → produce moves X→8 → ack(X) → assert the 8-delta still serves.

### F5 — FAL cost breaker under-counts (ignores retries + failed/blank generations)  `[VERIFIED high]`
**Doc:** `FULL_CODEBASE_REVIEW.md` H3.
**Problem:** `image_processing.py:231` sets `billed_mp` once for a *successful* fill, `0` on failure; `_fal_fill` retries up to 3× and blank/refused outputs trigger more billed generations. The breaker sums `billed_mp` → can read $0 while billing thousands.
**Fix:** count **every submitted generation** (retries + failed + blank) toward `billed_mp`/`fal_cost`. Combine with F13 (make the breaker global, not per-process).
**Verify:** mock FAL to fail-after-3-retries → assert `fal_cost` reflects 3 billed generations, breaker can trip.

### F6 — Magnitude-drift baseline merge is per-format not per-field  `[VERIFIED high]`
**Doc:** `FULL_CODEBASE_REVIEW.md` H4.
**Problem:** `magnitude_drift.py:142` `dict.update` replaces the whole `{field→median}` for a present format; a field absent one run loses its baselined median → a later 1000× unit error on that field is never compared → ships uncaught.
**Fix:** deep-merge per field — never drop a baselined field's median because it was absent this run.
**Verify:** baseline `slab={weight,length}` → run omitting weight → run with weight×1000 → assert FAIL.

### F7 — Batch name-strip corrupts real short leading words (`St Laurent`→`Laurent`)  `[VERIFIED high]`
**Doc:** `FULL_CODEBASE_REVIEW.md` H5 / `PIPELINE_MODULARITY_AUDIT.md` SC3.
**Problem:** `core/text.py:197` `looks_codey` treats every 2-letter lead as a code; fanout ≥2 in a batch strips it from all rows → wrong match key.
**Fix:** exclude short *pronounceable* leads (2-char containing a vowel: `El/La/St/Di/Mt`) from `looks_codey`; require no-vowel or a digit before treating a fanned-out lead as a code. Also reset `_lead_codes` unconditionally at the top of `adapt()`.
**Verify:** batch `["El Dorado","El Capitan"]` → assert match keys preserved.

## TIER 2 — Systemic roots (each fix resolves several mediums/lows at once)

### F8 — Cross-process shared-state strategy `[root of ~6 mediums + 4 lows]`
The code assumes one sequential writer; the deploy runs overlapping produce / build / GPU-Batch processes against the same shared state, all last-writer-wins. Pick a discipline per store:
- **S3 image manifest** (`images.py:105`, `treat.py:82`) → CAS with ETag/If-Match, or a single-writer invariant.
- **`config.db` `source_code` uniqueness** (`server.py:347`) → add a DB `UNIQUE` index (don't rely on the read-then-write app check).
- **Baselines JSON + `alias_writeback.csv`** (`writeback.py:54`, magnitude/scrape baselines) → lock or enforce single-writer.
- **`config.store.upsert_row`** (`store.py:268`) → make the two writes one transaction.
- **`atomic_write`** (`csvio.py:37`) → PID/random temp suffix, not a fixed `.tmp`.

### F9 — Audit every `except Exception` against the fail-loud invariant `[root of ~5 mediums]`
Each should distinguish "genuinely unreachable" from "misconfigured/broken" and surface the latter loud:
- `certify.py:84` — vocab check swallows all → returns PASS (can green-light a swapped column to auto). **Highest priority in this group.**
- `writethrough.py:110` — `record_catalog` swallows write-through failures (varieties silently never reach the ledger).
- `emit_catalog.py:63`, `variety_color.py:146`, `treat.py:47` — S3 helpers collapse AccessDenied into a benign heuristic.
- `run.py:422` — inventory-only run with a missing export reports success (real infra failure looks like "no change").
- `core/schema.py` — Pydantic `extra='ignore'` silently drops misnamed fields (**already live:** `ReviewFlag(..., detail=...)` at `product_state.py:107` is silently dropped). Set `extra='forbid'` on the models or add a construction guard.

### F10 — One scrape-completeness contract + completeness re-check at catalog
- Move the "is this scrape authoritative" decision into `scrapers/base.py` (one contract), covering: fetch-error-vs-end-of-pagination (`temmer.py:171`), empty-200 mid-catalog (`varsha.py:146`, ferraz, polonine), a **fractional floor** (detail-fetch failure ratio, not just `>0` rows), and `zucchi`'s under-reported-total case.
- Make `catalog.latest_run_dirs` (`catalog.py:40`) **skip an incomplete newest run** (mirror `run.find_scrape_file`) so an aborted scrape doesn't drop a source — **and** guard `prune_superseded_runs` so it never deletes the last *good* folder in favor of an empty newer one.

### F11 — Gate-abort contract (`run.py:371`)
`gates/__init__` says "a FAILED gate aborts before emit," but only the ingest gate aborts; clean/process FAILED is recorded and discarded. Either make clean/process FAILED abort (per the contract) or fix the contract doc — decide and make code+doc agree.

> RESOLVED (doc reconciled to code, no behavior change). The split is deliberate: the INGEST gate aborts, but the CLEAN and PROCESS gates are ADVISORY. Per-row `RejectReason`/`is_emittable` is the sole authority on what emits (only individually-valid rows ship), and an `auto`-mode source with any FAILED gate is BLOCKED from auto-loading via `auto_sources_blocked` (rc=1, which aborts the ordered build before catalog/emit); a review-mode source is already quarantined to the review queue. So a systemically-bad batch never auto-publishes. The `gates/__init__.py` docstring now documents this advisory contract. This finding line is retained as history.

## TIER 3 — Correctness mediums (sequence by exposure; see FULL_CODEBASE_REVIEW.md for each)
- **Fuzzy match auto-written-back → permanent EXACT/HIGH alias** (`match_variation.py:209`) — require operator confirmation before a fuzzy hit becomes a surface alias, or keep it at medium/flagged.
- **Weight parser is dimension-blind** (`derive.py:119`) — `Units.convert` must check `entry.dimension`; reject/flag a length/area unit in the weight field.
- **No per-row exception isolation** in match/reconcile/derive (`derive.py:620` et al.) — wrap the per-row resolver in try/except that flags the row, so one bad row never drops the whole source batch (the stated invariant).
- **Retired varieties still get combinations** (`tree_build.py:399`) — Key/Id space mismatch; test retired **Keys** against the export `key`, not `vid`.
- **A variety can vanish from the matcher** when its dedup survivor is independently excluded (`loaders.py:300`) — promote a loser when the chosen survivor is excluded.
- **De-watermark inpaints pink/red veining** (`image_processing.py:170`) — require stroke/text evidence, not just a pink-hue threshold, before masking.
- **Served product type/category from product row while gate checks the variation** (`sync.py:254`) — backfill `product.type` when `fill_variation_types` resolves it, or gate/payload from the same source.
- **`inventory_for` prefers derived `bundle_size` over explicit `raw_inventory_quantity`** (`product_state.py:78`) — folds into F1.
- **`_env_int` crashes config import on `--3`** (`settings.py:76`); **non-ASCII Authorization → TypeError not 401** (`server.py:375`); **migration parity hand-mirrored** (`store.py:74`) — three cheap robustness fixes.
